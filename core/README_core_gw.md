# Core-IP GW benchmark with QuAcK

Standalone driver for core ionization potentials in [QUESTDB](https://github.com/pfloos/QUESTDB/tree/main/charged/core_IPs). QuAcK is not modified. The runner uses the published CVS-FCI references (and available QUESTDB JSON values) for comparisons with CC methods and published G0W0@PBEh data.

## Protocol

| Method identifier | QuAcK calculation | SRG | QP equation |
| --- | --- | --- | --- |
| `g0w0` | G0W0@RHF | No | Nonlinear |
| `evgw` | evGW@RHF | **Yes, always**, `s=500` | Nonlinear |
| `qsgw` | qsGW@RHF | **Yes, always**, `s=500` | Static Hermitian |

All methods use **aug-cc-pCVTZ for non-hydrogen atoms**, augmented by **aug-cc-pVTZ for hydrogen**, full RPA screening (no TDA), no frozen core, and `eta=0`. `s=500` is the default hard-coded in the QuAcK routines; this runner does not edit it. The combined NWChem basis is cached at `core_gw_results/basis/aug-cc-pcvtz`. Hydrogen functions are added only if missing.

**There is exactly one evGW method:** `evgw` *always* activates SRG. Its job directory is `jobs/<molecule>/evgw/`, the CSV columns are `evgw_IP_eV`, `evgw_Z`, `evgw_status`, etc., and its method label in `orbitals.csv` and `statistics.csv` is `evgw`. There is no unregularized evGW calculation or automatic retry.

## Requirements

Use the Python environment that can run `$QUACK_ROOT/PyDuck.py`, with PySCF, NumPy, and Basis Set Exchange installed:

```bash
export QUACK_ROOT="$HOME/Work/QuAcK"  # adjust to your installation
python3 -m pip install pyscf numpy basis-set-exchange
```

The QuAcK executable must exist at `$QUACK_ROOT/bin/QuAcK`. Supply a local QUESTDB checkout via `--questdb /path/to/QUESTDB` or allow the script to download the XYZ/JSON files and cache them under the output directory.

## First calculations

```bash
python3 run_core_gw.py --test --prepare                 # prepare input files only
python3 run_core_gw.py --test --methods g0w0            # G0W0@HF only
python3 run_core_gw.py --test --methods evgw            # always SRG-evGW
python3 run_core_gw.py --test                           # G0W0 + SRG-evGW + SRG-qsGW
python3 run_core_gw.py --test --collect                 # rebuild CSVs from existing logs
```

The test set has seven targets in six molecules: CH4 (C 1s), NH3 (N 1s), H2O (O 1s), HF (F 1s), CO (C 1s and O 1s), and HCl (Cl 1s). For the full 84-target benchmark:

```bash
python3 run_core_gw.py --all
```

## Automatic integral cleanup (saves disk space)

After **every** QuAcK method finishes (including a failed calculation), the runner removes **only** that job's `jobs/<molecule>/<method>/int/` directory. It contains temporary one- and two-electron integral files generated by PyDuck. The runner keeps `quack.log`, `run.json`, the input files, geometries, protocol metadata, orbital maps, and all CSV results. The same cleanup occurs for already-cached successful jobs when the runner encounters them. No integral files are removed while QuAcK is running.

To reclaim disk space from **previously completed** jobs immediately, without rerunning calculations or rebuilding tables:

```bash
python3 run_core_gw.py --clean-integrals
```

This maintenance option searches only `core_gw_results/jobs/<molecule>/<method>/int/`, including directories made by older runner versions; it does not touch QuAcK's own `$QUACK_ROOT/int/` or QUESTDB. It reports how much space was recovered. Do **not** run it while a benchmark calculation is still running, because it could delete integrals in active jobs.

For debugging, disable automatic cleanup temporarily with:

```bash
python3 run_core_gw.py --test --keep-integrals
```

Unlike `--reset`, **`--clean-integrals` preserves all completed results**. Cleaned jobs can still be reused or collected from their existing logs; a forced rerun will regenerate the integral files and then delete them afterward.

## Reset the benchmark (deletes everything generated)

```bash
python3 run_core_gw.py --reset
```

This **permanently deletes the entire `core_gw_results/` directory**, including old `evgw_srg/` and unregularized `evgw/` jobs, all `quack.log` files, calculated results, CSV tables, downloaded QUESTDB files, the combined basis, and orbital-assignment cache. It **exits immediately** without starting any calculations. It does **not** touch the QuAcK source tree, the QUESTDB checkout, or the runner itself. `--reset` refuses unsafe destinations; for a custom `--out`, the folder must contain the runner's marker file.

After resetting, run the test again:

```bash
python3 run_core_gw.py --test
```

**Important for an existing benchmark directory:** old `jobs/<molecule>/evgw_srg/` logs are not automatically migrated or deleted by `--collect`. Only canonical `jobs/<molecule>/evgw/` logs are read by the revised script. Use `--reset` if you want a completely clean benchmark. If existing data are valuable, back up `core_gw_results/` before resetting.

`--force` differs from `--reset`: it recalculates selected jobs but keeps other logs and caches. Without `--force`, successful jobs are reused when their input fingerprints match.

## Output tables

All files are under `core_gw_results/` (or the directory specified by `--out`):

| File | Contents |
| --- | --- |
| `results.csv` | Core IPs, quasiparticle weights, errors, convergence flags and references. Exactly one evGW set of columns: `evgw_IP_eV`, `evgw_Z`, `evgw_status`, `evgw_error_eV`, `evgw_QP_failed_final`, `evgw_low_Z` |
| `statistics.csv` | Per-method MSE/MAE/RMSE/MaxAE and number of available results, using `evgw` as the evGW method label |
| `orbitals.csv` | All printed QuAcK orbital energies and Z values, using `evgw` as the evGW method label |
| `reference_manifest.csv` | Available CC, G0W0@PBEh, CVS-FCI values (and provenance) |
| `jobs/<molecule>/<method>/quack.log` | Original QuAcK text output |
| `jobs/<molecule>/<method>/protocol.json` | Calculation settings, basis and geometry fingerprints |
| `orbital_maps/*.json` | Provisional atomic-site/core-orbital assignments for `--all` |

Only the final evGW iteration's Newton-root failures are used to validate a target core IP. Failures of other orbitals remain diagnostic and do not automatically discard the target. `Z < 0.5` is flagged for inspection, not automatically excluded. The qsGW printed Z value is kept as a separate diagnostic, not interpreted as a Dyson quasiparticle residue.

## Limitations and scientific checks

- The script was tested on simulated QuAcK output but has **not** been validated end-to-end with a compiled QuAcK installation in this environment.
- Some QUESTDB JSON reference files are empty and CC/PBEh columns may be blank. The paper's hard-coded CVS-FCI fallbacks need cross-checking before reporting publication-quality statistics.
- For `--all`, check `orbital_maps/*.json` against the paper and QuAcK outputs, especially for symmetry-related or near-degenerate 1s orbitals and molecules containing two atoms of the same element.
- A converged quasiparticle root and a finite Z do not by themselves establish the correct physical assignment. Inspect suspicious energies/weights and the corresponding logs.
